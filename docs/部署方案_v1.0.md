# 部署方案_v1.0

> 适用范围：泡鱼终端（pyterm）平台侧（gx）+ 4 台 wrAgent 独立实例的标准化部署与运维。
> 版本基准：wragent `2.3.0`（commit=761d48e, go1.27.0）、wrgateway `1.1.2`（commit=761d48e, go1.27.1）、前端/后端以当前 `master` 为准。
> 状态日期：2026-09-28（已完成旧部署清理 + 4 台标准化重部 + 审批接入）。

## 0. 部署前置：确认 CPU 架构（必做）

**不同架构必须使用不同二进制，先查再部：**

```bash
uname -m        # x86_64 → *_linux_amd64；aarch64 → *_linux_arm64
```

| `uname -m` | 选用车件 | 说明 |
|---|---|---|
| `x86_64` | `releases/wragent_<ver>_linux_amd64` | 本次 4 台实测均为 x86_64 |
| `aarch64` | `releases/wragent_<ver>_linux_arm64` | ARM 服务器 |
| Windows | `releases/wragent_<ver>_windows_amd64.exe` | 不套本方案的 compose |

- 容器镜像 `alpine:3.20` 为多架构镜像，amd64/arm64 通用，无需按架构换镜像。
- 本方案所有 agent 服务器实测：**gx / nygpu / tx / m1k 均为 `x86_64`**，选 `linux_amd64`。

## 3. Agent 侧标准部署（4 台独立实例）

### 3.1 目录约定

```
/opt/wragent/
├── wragent                  # 二进制（按 uname -m 选 releases/wragent_2.3.0_linux_amd64）
├── config/
│   └── config.json          # 运行配置（空 agent_id/auth_token = 待注册模式）
└── docker-compose.yaml      # 标准 compose（见 3.2）
```

### 3.2 标准 docker-compose.yaml

```yaml
services:
  wragent:
    image: alpine:3.20
    container_name: wragent
    network_mode: host
    restart: unless-stopped
    environment:
      - TZ=Asia/Shanghai
    volumes:
      - /opt/wragent/config:/config:rw
      - /opt/wragent/wragent:/src/wragent:ro
    command: sh -c "cp /src/wragent /usr/local/bin/wragent && chmod +x /usr/local/bin/wragent && exec /usr/local/bin/wragent -config /config/config.json"
```

### 3.3 标准 config/config.json（待注册模式）

```json
{"server_url": "wss://gx.example.com:5588/api/ws/webrtc", "agent_id": "", "auth_token": ""}
```

### 3.4 部署步骤

| # | 步骤 | 命令/要点 |
|---|---|---|
| 1 | 确认架构 | `uname -m`（见第 0 节），x86_64 用 `wragent_2.3.0_linux_amd64` |
| 2 | 建目录 | `mkdir -p /opt/wragent/config` |
| 3 | 传二进制 | 单一来源：gx `/ppy_prj/pyterm/releases/` → `/opt/wragent/wragent`，`chmod +x` |
| 4 | 写配置 | `config/config.json` 用 3.3（agent_id/auth_token 留空 → 走待注册审批） |
| 5 | 写 compose | `/opt/wragent/docker-compose.yaml` 用 3.2（nygpu 需 `sudo mv` 落位，ubuntu 不能重定向写 root 目录） |
| 6 | 启动 | `cd /opt/wragent && docker compose up -d`（nygpu 加 `sudo`） |
| 7 | 取注册地址 | `docker logs wragent --tail 20` → `https://gx.example.com:5588/agent/s/<sid>`，**30 分钟内有效** |
| 8 | 审批/命名 | 见第 4 节 |
| 9 | 验证 | 日志 `注册成功` + `已接收服务端ICE配置`；`docker exec wragent /usr/local/bin/wragent -v` 输出 2.3.0 |

> 旧版散乱部署（gx systemd、nygpu 旧容器、tx nohup、m1k 双实例 systemd+docker）已于 2026-09-28 全部清理，见第 6 节。

## 4. 注册与审批

| 流程 | 端点 | 说明 |
|---|---|---|
| 查看待注册 | `GET /api/admin/agents/pending`（Bearer 管理员） | 返回 `_setup_sessions`（30 分钟内）：sid / agent_id / agent_name |
| 审批 | `POST /webrtc/agents/setup` body `{"sid": "..."}` | **不带 `/api` 前缀**；返回 `{ok, agent_id}`；或在管理台「待注册」处点批准 |
| 改名/备注 | `PUT /api/admin/agents/{agent_id}` body `{"name","remark"}` | 部署后统一命名（见第 5 节） |
| 一键注册（替代） | 浏览器打开日志里的 `/agent/s/<sid>` | sid 过期后 agent 重连会重新签发 |

管理台登录：`admin / change_me_pass`（登录接口 `POST /api/auth/login`，返回字段为 `token`）。

## 8. 故障排查

| 现象 | 原因 | 处置 |
|---|---|---|
| 日志 `等待认证完成... (30分钟内有效)` | 待注册未审批 | 30 分钟内走第 4 节审批；过期 agent 重连会自动换新 sid |
| 写 `/opt/wragent/*` 报 `Permission denied` | ubuntu 下 shell 重定向跑在 root 属主目录 | 先写 `/tmp` 再 `sudo mv` |
| `POST /api/webrtc/agents/setup` 返回 `Method Not Allowed` | 审批端点不带 `/api` 前缀 | 正确路径 `POST /webrtc/agents/setup` |
| 审批后 agent 不在线 | config.json 与 DB token 不一致 | 核对 `agents.token` 与 config；或按 7.3 重建 |
| E2E 找不到 `local-agent-2` | 该行反复丢失 | 按 7.3 重建 |
| `bash scripts/publish-github.sh` 报 `[scan] 失败` | 新敏感词未进字典 | 补 `scripts/publish-dict.tsv` + 脚本内 `WORDS` |
