## 3. Agent 侧标准部署（4 台独立实例）

### 3.1 目录约定

```
/opt/wragent/
├── wragent                  # 二进制（按 uname -m 选 releases/wragent_2.3.1_linux_amd64）
├── config/
│   └── config.json          # 运行配置（空 agent_id/auth_token = 待注册模式）
└── docker-compose.yaml      # 标准 compose（见 3.2）
```

### 3.2 标准 docker-compose.yaml（三件套宿主控制台模式）

```yaml
services:
  wragent:
    image: alpine:3.20
    container_name: wragent
    network_mode: host
    pid: host
    privileged: true
    restart: unless-stopped
    environment:
      - TZ=Asia/Shanghai
      - HOST_CONSOLE=1
      - PERSIST_BIN=/wragent/wragent
    volumes:
      - /opt/wragent:/wragent:rw
      - /opt/wragent/config:/config:rw
      - /:/host:rw
    command: sh -c "cp /wragent/wragent /usr/local/bin/wragent && chmod +x /usr/local/bin/wragent && exec /usr/local/bin/wragent -config /config/config.json"
```

三件套的作用（缺一不可）：

| 配置 | 作用 |
|---|---|
| `pid: host` | 容器内可见宿主 PID 1，nsenter 才有目标 |
| `privileged: true` | 放开 `setns()` 权限，否则进入宿主命名空间报 `Operation not permitted` |
| `HOST_CONSOLE=1` | 触发 Agent 的宿主控制台分支：`nsenter -t 1 -m -u -i -n -p -- <shell>` |
| `PERSIST_BIN=/wragent/wragent` | 热升级后把新二进制持久化回宿主 `/opt/wragent/wragent`（容器重启不回退） |
| 架构感知升级 | 2.3.3 起 agent 注册上报 `arch`，控制台升级 URL 按 `linux-{arch}` 生成（arm64 节点不再误下 amd64） |
| 网关 WS 契约 | 浏览器经网关连接对 `wss://<gw>:5599/ws`（前端已归一化补 `ws`；网关根路径亦兼容）；网关 TLS 服务禁用 HTTP/2（`TLSNextProto` 空表），否则 gorilla WS 升级 400 |
| `- /:/host:rw` | 宿主根文件系统挂载点（诊断用） |
| `- /opt/wragent:/wragent:rw` | 目录挂载：boot 复制源 + PERSIST_BIN 持久化目标（替代旧的文件 `:ro` 挂载） |

- `network_mode: host` 依旧保留（WebRTC 回连走宿主网络）。
- **命名空间参数为显式列表 `-m -u -i -n -p`**：alpine busybox `nsenter`（v1.36.1）**没有 `-a` 选项**，Agent 2.3.1 起改用显式列表，与 GNU `nsenter -a` 行为等价，busybox/GNU 通用。
- 效果：浏览器里打开的「Agent 本地控制台」= **宿主机控制台**（root、宿主 rootfs、init=systemd），而非容器内 busybox shell。

## 4. 注册与审批

| 流程 | 端点 | 说明 |
|---|---|---|
| 管理台登录 | `POST /api/auth/login` body `{"username":"admin","password":"change_me_pass"}` | 返回字段 `token`（字段名不是 `admin`，缺 username/password 会 422） |
| 查看待注册 | `GET /api/admin/agents/pending`（Bearer 管理员） | 返回 `_setup_sessions`（30 分钟内）：sid / agent_id / agent_name |
| 审批 | `POST /webrtc/agents/setup` body `{"sid": "..."}` | **不带 `/api` 前缀**；返回 `{ok, agent_id}`；或在管理台「待注册」处点批准 |
| 改名/备注 | `PUT /api/admin/agents/{agent_id}` body `{"name","remark"}` | 部署后统一命名（见第 5 节） |
| 一键注册（替代） | 浏览器打开日志里的 `/agent/s/<sid>` | sid 过期后 agent 重连会重新签发 |

- 注册为严格校验（S5）：必须已有 DB `agents` 行且 token 与 config 完全一致，否则 `注册失败` 并进入 Tailscale 风格 setup 模式。
- 审批通过后 **Agent 会自动把新 token 写回 config.json**，无需手工填。

## 8. 故障排查

| 现象 | 原因 | 处置 |
|---|---|---|
| 日志 `等待认证完成... (30分钟内有效)` | 待注册未审批 | 30 分钟内走第 4 节审批；过期 agent 重连会自动换新 sid |
| 控制台只见容器 shell / `unrecognized option: -a` | Agent 非 2.3.1 或 compose 缺三件套 | 升级 2.3.1 并套用 3.2 compose |
| nsenter 探针报 `Operation not permitted` | 容器未 `privileged: true` | 套用 3.2 compose 后 `up -d --force-recreate` |
| `docker compose` 报 `unknown command` | 该机无 v2 插件（nygpu） | 改用 `sudo docker-compose`（1.29.2） |
| nygpu v1 `up -d --force-recreate` 报 `KeyError: 'ContainerConfig'` | compose 1.29 与 Docker 29 不兼容（重建路径） | 删掉残留半成品容器后**全新创建**：`sudo docker ps -a \| grep wragent` → `sudo docker rm -f <残留名>` → `sudo docker-compose up -d` |
| 出包报 `文本文件忙`（ETXTBSY） | `./wragent/wragent` 正被平台容器执行 | 先 `docker compose stop wragent wragent2` 再出包（见 7.4） |
| 本地双 Agent `注册失败:`（detail 为空）+ 进 setup 模式 | DB 行丢失或 token 与 config 不一致 | 第 4 节审批恢复（token 自动回写）；或 7.3 方式 B |
| 登录接口 422 `Field required username/password` | body 字段名用错 | `{"username":"admin","password":"..."}`，勿用 `admin` 字段 |
| `POST /api/webrtc/agents/setup` 返回 `Method Not Allowed` | 审批端点不带 `/api` 前缀 | 正确路径 `POST /webrtc/agents/setup` |
| 写 `/opt/wragent/*` 报 `Permission denied` | ubuntu 下 shell 重定向跑在 root 属主目录 | 先写 `/tmp` 再 `sudo mv` |
| E2E 找不到 `local-agent-2` | 该行丢失 | 按 7.3 重建或第 4 节审批 |
| `bash scripts/publish-github.sh` 报 `[scan] 失败` | 新敏感词未进字典 | 补 `scripts/publish-dict.tsv` + 脚本内 `WORDS` |
