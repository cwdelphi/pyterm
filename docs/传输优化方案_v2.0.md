## 0. 设计决策（无兼容约束下的取舍）

| # | 决策 | 结论 | 理由 |
|---|---|---|---|
| D1 | 网关是否解析 payload | **永不解析，纯 `[1B type][payload]` 透传** | 现状 `handler.go:460-467` 每 24KB `Unmarshal→Marshal` 注入 `type`/`room_id`；type 已是首字节、room 由 session 绑定，**注入本身是多余的** |
| D2 | 控制帧是否二进制 | **保持 JSON，但对网关不透明** | `ssh_connect`/`error` 每会话 1 次，非热点；JSON 可调试性收益 > 编解码成本 |
| D3 | 信令（SDP/ICE）是否二进制 | **保持 JSON，仅消除 `data`/`sdp` 双写** | SDP 本身是文本协议，每连接 5–30 次，非帧级频率 |
| D4 | DataChannel 数量 | **拆 4 条**（interactive / bulk / tcp-tunnel / speedtest） | 单通道 `ordered=true` 导致 VNC/SFTP 大块重传 **HOL 阻塞终端帧**；SCTP 多流同 association，开销极小 |
| D5 | 可靠性参数 | **全部 ordered + 完全可靠**，不做半可靠 | VNC 是 zlib 连续流、SFTP 是文件、终端要 seq 语义，**三者都不能丢**；分流已解决 HOL，无需牺牲正确性 |
| D6 | Detached 模式 | **采用**（v1.2 未完成项） | 读侧由己方提供 buffer → 消除 pion 每消息分配；写侧控制消息边界 |
| D7 | permessage-deflate | **按帧大小分级开关**，非全开全关 | 终端 bulk 文本可压（省带宽），10B 按键压缩是纯浪费（`handler.go:26` 现状全开） |
| D8 | `relay` 包 | **删除**，新纯中继设计取代 | 零 import 死代码；`bridge.go:19`/`webrtc.go:22` 零调用 |
| D9 | 协商/回退/灰度 | **全部不要** | 三端同窗部署（§6.2），失败整体回滚 commit |

## 3. 协议设计 v2.0

### 3.1 统一帧格式

**全链路一致（浏览器 WS ↔ 网关 ↔ DC ↔ Agent）：**

```
frame = [1B type][payload]
```

- WS 消息边界 = 帧边界；SCTP 消息边界 = 帧边界 → **不需要 length 字段**
- **网关永不解析 payload**，只看 `type` 字节决定走哪条 DC/WS 队列
- `room_id` 由 session 绑定（连接级），**不进帧**
- 类型分区：`0x01–0x0F` 交互 · `0x10–0x1F` 文件 · `0x20–0x2F` 桌面 · `0x30–0x3F` 隧道 · `0x40–0x4F` 控制

### 3.2 帧类型表（表7）

| type | 名称 | 方向 | payload | 频率 | 变化 |
|---|---|---|---|---|---|
| `0x01` | TERM_OUT | A→B | `[4B BE seq]` + raw utf8 | 极高 | 现 `0x00`，重编号 |
| `0x02` | TERM_IN | B→A | raw utf8 | 高 | 原 `0x00` |
| `0x03` | TERM_ACK | B→A | `[4B BE seq]` | ≤5/s | 不变 |
| `0x04` | RESIZE | B→A | `[2B cols][2B rows]` | 低 | **JSON → 定长 4B** |
| `0x10` | SFTP_CMD | B→A | `[1B op][4B reqId][2B metaLen][meta JSON]` | 低 | req_id UUID → **4B 计数器** |
| `0x11` | SFTP_META | A→B | `[4B reqId][2B metaLen][meta JSON]` | 低 | 去 type/room 注入 |
| `0x12` | SFTP_CHUNK | A→B | `[4B reqId][2B idx][2B cnt][raw bytes]` | 每 24KB | **去 JSON 壳 + 去 base64** |
| `0x13` | SFTP_UPLOAD | B→A | `[4B reqId][2B idx][2B cnt][raw bytes]` | 每 24KB | **去二次 base64** |

| `0x30–0x35` | TUNNEL | — | 既有二进制 | 高 | 不变 |

### 3.3 DataChannel 分流（表8）

| DC label | 承载 | ordered | 可靠 | 背压策略 |
|---|---|---|---|---|
| `interactive` | TERM_*、VNC_INPUT、RESIZE、HEARTBEAT、CLOSE | true | 完全 | 阈值 16KB，**超限丢最旧**（有 seq 空洞检测兜底） |

### 3.4 背压与发送队列（表9）

| 项 | 现状 | 新设计 |
|---|---|---|

| WS 压缩 | `EnableCompression:true` 全帧压缩 | 按帧切 `conn.EnableWriteCompression(len>1024)`：**终端 bulk 压、小帧不压** |
| DC 压缩 | 无（正确） | 保持无（VNC 已 zlib、SFTP 是文件） |
| 网关读 | `ReadMessage`→`io.ReadAll(≥512B)` 每帧分配 | `NextReader()` + 会话级复用 64KB buf + `dc.Send(buf[:n])`（pion 同步拷贝，buf 可复用） |
| 网关写 | `dc.Send` + API 模式 | **Detached `rwc.Write`**（v1.2 未完成项落地） |
| 浏览器收 | `data.slice(1)` + `payload.slice(4)` 各一次整包拷贝 | `new Uint8Array(buf, off, len)` **视图** |
| 浏览器发 | 每次 `new Uint8Array(1+len)` 拷贝 | interactive/bulk 各持 1 个复用发送 buffer |
| PTY 读 | `make([]byte, 32*1024)` 每循环 | 64KB + 会话级复用（`localterm.go:128`） |
