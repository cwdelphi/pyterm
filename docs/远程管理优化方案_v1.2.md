## 2. 实现要点

### 2.1 Host key（S6a）

- 新建 `wragent/webrtc/hostkey.go`：
  - 策略 `tofu`（默认）/ `strict` / `insecure`。
  - 基于 `golang.org/x/crypto/ssh/knownhosts`；TOFU 未知主机追加 known_hosts，密钥不匹配一律拒绝（防 MITM）。
  - `InitHostKeyConfig` 同步 once；known_hosts 默认 `config` 同目录（可 `HOST_KEY_POLICY` / `KNOWN_HOSTS_FILE` 配置）。
- `signal.go` SSH 握手 `HostKeyCallback: HostKeyCallback()`。
- `main.go` 启动时读 `config.HostKeyPolicy` / `KnownHostsFile` 初始化。
- wrgateway 不直连目标机，无 host key 场景。

### 2.2 凭据加密（S6b）

- 新建 `app/crypto.py`：Fernet；前缀 `enc:v1:`。
- 密钥：`CREDENTIAL_KEY`（合法 Fernet key）优先，否则由 `JWT_SECRET` 派生（sha256 `"pyterm.cred.v1:"+secret`）。
- **写路径加密**：`_write_user_ssh_list`（password/vnc/rdp + SFTP 配置）、`sync_db` 写、`database.py` 种子（VNC ref_local/ref_remote、per-user/global SftpConfig）。
- **读路径解密**：`_read_user_ssh_db`、`sync_db` 读、`get_password`/SFTP 客户端配置。
- 幂等：`encrypt_secret` 对已带前缀值不重加密；遗留明文读原样返回，下次写自动加密。
- `ssh_list` API 剥离 `password`/`vnc_password`/`rdp_password`（顺带修复 rdp_password 泄漏）；补读 rdp_port/rdp_password/rdp_domain/rdp_resolution。
- `app/requirements.txt` 加 `cryptography>=42.0.0`；`docker-compose.yaml` `CREDENTIAL_KEY=` 占位。
- `ssh_keys` 表暂无 API 端点，本期不加密。

### 2.3 终端 seq/ack（协议破坏性变更）

- **帧格式（agent→browser）**：`[0x00][4B BE seq][payload]`；seq 在 `sendDCMsg` 创建时分配，背压丢帧留下空洞。
- 新前缀：agent `MsgAck=0x03` / gateway `MSG_ACK` / 浏览器 `MSG_ACK`。
- 浏览器 `handleTerminalFrame`：剥 4B seq、统计 gap 并 WARN 日志、**200ms 节流**回传 `[0x03][4B BE]`（gateway 走 signalWs binary，直连走 DC）。
- agent `handleTerminalAck`：记录 lastAckSeq，ack 落后 tx 且有 dropped 时打诊断日志（不做重传——保最新画面）。
- gateway：二进制 WS 帧直发 DC（含 0x03）；JSON `terminal_ack` → binary `[0x03][seq]`；DC 二进制透传含 0x00+seq。
- **部署约束**：agent / gateway / web **必须同步部署**（旧 agent 无 seq 会被浏览器误剥 4 字节）。
- VNC 不加 seq（画面可丢帧，不可用终端补偿语义）。

## 4. Gateway 信令合并评估（推迟）

**现状**：网关 `Session.RoomID` 1:1 单值；浏览器二进制帧**不带 room_id**，JSON 帧带 `room_id`。直连模式已用 `SharedDirectSignal` 按 `room_id` 分发合并一条 WS。

**为何推迟**：

1. 合并要求二进制终端/VNC 帧携带路由（改帧格式或包一层），属**再次破坏性协议改造**，与 P3 seq 变更叠加风险高。
2. gateway 模式每浏览器页通常只开 1 个 room（终端/VNC/探针），多标签共用网关的收益低于直连模式 P4。
3. `Session.RoomID` 清理、背压 `bpPending`、`pendingMsgs` 均假设单 room，多路复用需重构 session 生命周期。

**结论**：P3 **不实施** gateway 信令合并；若后续确需，单独开 P5 并做协议 version 字段（如帧头 `ver` 字节）避免与 seq/ack 冲突。
