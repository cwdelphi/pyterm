## 1. 现状技术分析

### 1.1 链路架构（两模式）

| 模式 | 路径 | SFTP 旧格式 | 目标格式 |
|---|---|---|---|
| 直连 DC | 浏览器 ⇄ DC ⇄ wragent | JSON 文本 + base64 | `[type][sub][二进制头][raw]` |
| 网关中继 | 浏览器 ⇄ WS ⇄ wrgateway ⇄ DC ⇄ wragent | 上行 JSON text；下行 agent JSON → 网关 `Unmarshal→Marshal` 注入 `type/room_id` → WS text | **网关零解析纯透传** |

**路由闭合证据**：上行二进制 WS → `handler.go:184-198` 直发 DC → `signal.go:1630-1647` `MsgSFTPRequest` 二进制分支；下行 `sendSftpMeta/sendSftpChunk` → `handler.go:460-465`（本轮新增）→ `writePump:309-319` 首字节 `≤0x2F` 判 `BinaryMessage` → 前端 `webrtc.ts:572`（WS）/`:1029`（DC）→ `handleSftpFrame`。

### 1.2 帧格式对照

| 维度 | 旧协议 | 目标（工作区实现） | 差异 |
|---|---|---|---|
| SFTP 请求 | `{type,room_id,op,req_id(UUID 36B),path,content}` | `[0x10][sub][op:1][reqId:4BE][metaLen:2BE][meta JSON]` | 去 `room_id`、reqId −32B、免 1 次 stringify |
| 上传分片 | `content` 调用方 base64 → JSON 切片 → 每片再 base64（**双重**） | `[0x10][sub=0x01][reqId:4B][idx:2B][cnt:2B][raw]` | **×1.778 → ×1.0** |
| 响应元数据 | JSON（含 type/room 注入） | `[0x11][sub=0x00][reqId:4B][metaLen:2B][meta JSON]` | 网关不再解析注入 |
| 下载分片 | agent `base64(content)` → JSON 壳 → 再 base64（**双重**） | `[0x11][sub=0x01][reqId:4B][idx:2B][cnt:2B][raw]` | **×1.778 → ×1.0** |
| VNC 上行 `0x23` | `{type:"vnc_input",data:<b64>,room_id}`（工作区已回退到此） | `[0x23][raw RFB]`（`FrameScratch` 复用） | `raw×1.333+60~70B` → `raw+1B` |

## 2. 目标协议设计

### 2.1 帧头

| 帧 | 布局 | 说明 |
|---|---|---|
| 请求 CMD | `[0x10][sub=0x00][op:1][reqId:4BE][metaLen:2BE][meta JSON]` | `meta` 仅 `path/old_path/new_name/chunks` |
| 请求 UPLOAD | `[0x10][sub=0x01][reqId:4BE][idx:2BE][cnt:2BE][raw]` | 24KB+9 < 64KB DC 上限 |
| 响应 META | `[0x11][sub=0x00][reqId:4BE][metaLen:2BE][meta JSON]` | `{type,op,path,ok[,detail][,items][,chunks]}` |
| 响应 CHUNK | `[0x11][sub=0x01][reqId:4BE][idx:2BE][cnt:2BE][raw]` | read 内容或超大 meta 分片 |
| Op 码 | `1 list · 2 read · 3 write · 4 mkdir · 5 rename · 6 delete · 7 stat` | 前后端常量表由单测锁死 |
| reqId | uint32 计数器 `(n+1)>>>0` | 替代 UUID：−32B、免哈希 |

### 2.2 时序与异常

| 场景 | 顺序 | 失败语义 |
|---|---|---|
| write | UPLOAD×n → CMD(`chunks=n`)（有序保证分片先达） | `takeSFTPUpload` false → `上传分片不完整` |
| read | CHUNK×n → META(带 `chunks`) | 前端按 reqId 聚合；`arm()` 续期、总时长封顶 4× |
| 小结果 | 单 META | `metaLen>32KB` 走 `sendChunkedMeta` |
| 空文件 | `cnt=0`（无 CHUNK）+ META | 前端返回 0 字节 |
| 异常帧 | 头不足/越界/子类型错 | 逐项 `sendDCSftpError`，不 panic |
| 未知 op | `default` | 回「未知操作」 |

### 2.3 网关纯中继规则（母方案 D1）

| 方向 | 规则 |
|---|---|
| WS→DC | 二进制帧整帧直发（`:184-198`）；仅 `0x00` 终端帧走背压入队 |
| DC→WS | `0x11` 原样 `select{SendCh<-data; <-Done}`（**可靠不丢**） |
| WS 写出 | 首字节 `≤0x2F` → Binary，否则 Text（JSON 控制面） |
| 删除 | JSON `case "sftp_request"` 路由与转换分支 |
