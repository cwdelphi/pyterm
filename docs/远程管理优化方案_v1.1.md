## 2. 实现要点

### 2.1 P1 背压（agent + gateway）

- **wragent** `sendDCMsg`：`BufferedAmount > 64KB` 且 prefix 为终端/VNC 时，进入 `dcWriteState` 队列（上限 256KB），满则丢最旧并 5s 限频日志；后台 goroutine 轮询低水位（≤32KB）冲刷。
- **wrgateway**：浏览器→DC 终端帧（binary 与 JSON `terminal_data`）同样入 `Session.bpPending`，`flushSessionBP` 冲刷；DC OnOpen 时清空队列统计。
- DC OnClose 清理 `dcWriteStates`，防泄漏。

### 2.2 P4 直连信令复用

- `SharedDirectSignal`：按 `roomId` 注册成员；共享一条 WS；消息带 `room_id` 分发，无 room 广播；`heartbeat_ack` 由 hub 消费。
- join 时若已 OPEN：对该成员 `onOpen` + 补发 `connect_agent`；hub 维护 refcount，最后一员 leave 时 teardown。
- **gateway 模式不合并**（网关 `Session.RoomID` 单值，合并需协议改动 → P3）。

### 2.3 P8 close()

- 失败路径诊断等待 3000→**800ms**；首字节等待 500→**200ms**；`intentionalClose` 阻止 close 触发的自动重连。

### 2.4 R4 自动重连

- **直连**：hub 断线且非 us 关闭 → 指数退避重连（1s×2^n ≤30s + jitter），重连后对全部成员 `onOpen` + 重发 `connect_agent`。
- **gateway**：`signalWs.onclose` 且非 intentional → `scheduleSignalReconnect`（最多 8 次），重建 PC/DC 后重连信令。
- **ack 超时**：15s 心跳；**45s** 无 `heartbeat_ack` 视为假活 → hub/gateway 强制 close 触发重连。
- 成员 `handleSignal` 更新 `lastAckAt`。
